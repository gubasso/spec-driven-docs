# Migration from 0.1.4 to 0.1.5

## Applicability

Apply this guide to instances whose manifest reports `0.1.4`.

## Preconditions

1. Run offline verification.

   ```bash
   .spec-driven-docs/verify.sh --target /path/to/your-project --offline
   ```

## Managed changes

- `gates/canon/delivered-domain.sh` holds `.pre-commit-hooks.yaml` against a fresh render of
  `instance/gates.json` rather than against its identifiers alone, and requires each profile to
  project exactly the declared root. Both gates stay on the canon side and reach no instance.
- `scripts/render-gate-block.sh` doubles an apostrophe inside a single-quoted YAML scalar and
  quotes the `name` field, so a declaration carrying either renders valid YAML.
- `scripts/upgrade.sh` refuses to remove a dropped destination that is absolute, carries a `..`
  segment, or is reached through a symlink, and no longer reports success when a removal was
  refused or failed.

## Living rule-ID changes

- None.

## Local integration action

1. Re-adopt `TEMPLATE-spec.md`. It carried a relative link into `method/`, which the canon keeps
   and never delivers, so the link resolved nowhere in an instance and failed a link check.

   ```bash
   cp <canon-checkout>/templates/TEMPLATE-spec.md <docs_root>/specs/TEMPLATE-spec.md
   ```

## Verification

1. Run the project gate and offline verifier.

   ```bash
   .spec-driven-docs/verify.sh --target /path/to/your-project --offline
   pre-commit run --all-files
   ```

## Rollback

1. Restore the project snapshot taken before the upgrade.
