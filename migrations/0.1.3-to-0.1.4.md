# Migration from 0.1.3 to 0.1.4

## Applicability

Apply this guide to instances whose manifest reports `0.1.3`.

## Preconditions

1. Run offline verification and note every adopted file the verifier reports as drifted.

   ```bash
   .spec-driven-docs/verify.sh --target /path/to/your-project --offline
   ```

## Managed changes

- No projected file changes. The gates that enforce the moved rules live under `gates/canon/` and
  are never delivered.

## Living rule-ID changes

The release rules moved out of the `distribution` domain into a `release` domain of their own, and
their identifiers moved with them. An instance never ran the gates that print these, so the rename
reaches an instance only through the spec it adopted.

- `distribution:versions-are-semantic-and-aligned` is now `release:versions-are-semantic-and-aligned`.
- `distribution:a-tag-derives-from-the-version-file` is now `release:a-tag-derives-from-the-version-file`.
- `distribution:a-released-version-is-not-re-authored` is now `release:a-released-version-is-not-re-authored`.
- `distribution:a-release-carries-its-migration-guide` is now `release:a-release-carries-its-migration-guide`.
- `distribution:license-declares-both-halves` is now `release:license-declares-both-halves`.
- `distribution:the-delivered-gate-set-is-declared-once` is now
  `release:the-delivered-gate-set-is-declared-once`.
- `distribution:a-canon-gate-is-not-delivered` is now `release:a-canon-gate-is-not-delivered`.

## Local integration action

1. Re-adopt `SPEC-distribution.md`. An adopted file is the instance's own copy and the upgrade
   leaves it alone, so the seven release rules stay in your tree until you replace it. They name
   gates under `gates/canon/`, which your instance does not have, and
   `docs-specs:verification-names-a-live-hook` fails on the first one it reaches.

   ```bash
   cp <canon-checkout>/_docs/specs/SPEC-distribution.md <docs_root>/specs/SPEC-distribution.md
   ```

2. Do not adopt `SPEC-release.md`. It states rules only the canon can verify, and no profile
   installs it.

3. Reapply any rule your project added to its own copy of `SPEC-distribution.md`.

## Verification

1. Confirm every rule resolves to a gate the instance holds.

   ```bash
   .spec-driven-docs/verify.sh --target /path/to/your-project --offline
   pre-commit run spec-verify-hooks-exist --all-files
   ```

## Rollback

1. Restore the project snapshot taken before the upgrade.
