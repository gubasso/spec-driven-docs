# Migration from 0.1.2 to 0.1.3

## Applicability

Apply this guide to instances whose manifest reports `0.1.2`.

## Preconditions

1. Run offline verification.

   ```bash
   .spec-driven-docs/verify.sh --target /path/to/your-project --offline
   ```

## Managed changes

- No projected file changes. The corrections are to `scripts/upgrade.sh`, which an instance runs
  from the canon checkout rather than from its own payload.
- `upgrade.sh` no longer treats a managed file the canon relocated as a conflict. It asks only
  whether the copy on disk still matches the hash the instance recorded, so a payload reorganized
  upstream is upgradable instead of reporting every managed file as a conflict at once.
- `upgrade.sh` now removes a managed file the new version stopped owning, and names each one it
  removed. Prior releases left it on disk, still running from a payload that no longer claimed it.
- `instantiate.sh` reads the projected directory from the profile's `managed_directories` instead of
  naming it internally.

## Living rule-ID changes

- None.

## Local integration action

1. None.

## Verification

1. Run the project gate and offline verifier.

   ```bash
   .spec-driven-docs/verify.sh --target /path/to/your-project --offline
   pre-commit run --all-files
   ```

## Rollback

1. Restore the project snapshot taken before the upgrade.
