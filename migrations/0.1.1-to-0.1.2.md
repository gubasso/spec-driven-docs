# Migration from 0.1.1 to 0.1.2

## Applicability

Apply this guide to instances whose manifest reports `0.1.1`.

## Preconditions

1. Run offline verification.

   ```bash
   .spec-driven-docs/verify.sh --target /path/to/your-project --offline
   ```

2. Record which gate ids your project already wires by hand, so the ones the managed block now
   carries can be removed from wherever you wired them.

   ```bash
   grep -n 'id: ' .pre-commit-config.yaml
   ```

## Managed changes

- The managed pre-commit block now wires every delivered gate. It previously named
  `spec-driven-docs-verify` alone, so a projected gate ran only where a project had wired it by hand.
- Four gates are no longer projected: `license-split.sh`, `version-source-of-truth.sh`,
  `test-gates.sh`, and `delivered-domain.sh` check invariants the canon alone has. Delete them from
  `.spec-driven-docs/hooks/` if an earlier install left them there.
- `verify.sh` recognizes a managed-block entry by its path separator rather than a leading dot.

## Living rule-ID changes

- `distribution:the-delivered-gate-set-is-declared-once` is new.
- `distribution:a-canon-gate-is-not-delivered` is new.

## Local integration action

1. Remove any hand-wired copy of a delivered gate from `.pre-commit-config.yaml`. The managed block
   between the `# BEGIN spec-driven-docs managed` and `# END spec-driven-docs managed` markers now
   carries them, and a second entry runs the same gate twice.
2. Run the hooks once over the whole tree. Gates that were inert before this release run now, so a
   document that was never gated may fail for the first time.

   ```bash
   pre-commit run --all-files
   ```

## Verification

1. Confirm every delivered gate is wired.

   ```bash
   .spec-driven-docs/verify.sh --target /path/to/your-project --offline
   pre-commit run --all-files
   ```

## Rollback

1. Restore the project snapshot taken before the upgrade.
