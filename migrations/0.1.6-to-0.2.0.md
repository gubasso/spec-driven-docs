# Migration from 0.1.6 to 0.2.0

## Applicability

Apply this guide to instances whose manifest reports `0.1.6`.

## Preconditions

1. Install the `sdd` binary; the distribution is now one executable rather than a vendored
   script payload.

   ```bash
   cargo install spec-driven-docs
   ```

2. Run offline verification with the installed payload.

   ```bash
   .spec-driven-docs/verify.sh --target /path/to/your-project --offline
   ```

## Managed changes

- The vendored payload is retired. `sdd upgrade` removes `.spec-driven-docs/verify.sh` and every
  file under `.spec-driven-docs/hooks/`; the gates and the verifier now live inside the binary.
- The managed pre-commit block is rewritten: every gate entry becomes `sdd gate <id>` and the
  verifier entry becomes `sdd verify`, both `language: system`. Hook ids are unchanged.
- The manifest moves to `schema_version` 2: `canon_ref` is dropped, and the managed set shrinks
  to the markdownlint configurations. `installed_at` is preserved.
- The 79-column report gate now measures display columns rather than bytes, so a body carrying
  wide characters may report a different count than before.

## Living rule-ID changes

- None. Adopted specs are yours and are not rewritten; `sdd upgrade` reports upstream rule IDs
  your local specs do not yet state.

## Local integration action

1. Ensure `sdd` is on the PATH of everyone who runs the hooks, including CI.

## Verification

1. Run the offline verifier and the project gate.

   ```bash
   sdd verify --target /path/to/your-project
   pre-commit run --all-files
   ```

## Rollback

1. Restore the project snapshot taken before the upgrade.
