# Method

Spec-driven documentation separates current agreement from historical rationale and executable
behavior. Specifications state what binds, decision records state why a choice was made, and code or
content shows the observed result.

Start with [the model](./00-model.md), use [placement](./01-placement.md) to choose a home, then follow
the chapter that owns the artifact being changed. [The checklist](./99-checklist.md) is the pre-merge
review surface.

To apply the method in another project, use the [instance guide](../instance/README.md) and choose the
codebase or knowledge-base profile. Stable authoring seeds are available under
[templates](../templates/).
